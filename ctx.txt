### Options for Real-Time Sync

**A. Polling** (simplest)
- Frontend polls `GET /api/layout` every N seconds
- Compare with current layout, apply if different
- Drawback: Delay, unnecessary requests

**B. WebSocket broadcast** (recommended)
- You already have WebSocket infrastructure
- Server broadcasts a `LAYOUT_CHANGED` message to all connected clients when layout is saved
- Clients receive it and call `api.fromJSON()` to update
- Instant, efficient

**C. Server-Sent Events (SSE)**
- Dedicated event stream for layout updates
- Adds another connection type to manage

---

### Recommendation

Since you already have WebSocket connections per terminal panel, option **B** makes sense. The implementation would add:

1. **New message type**: `LAYOUT_CHANGED = 11`
2. **Backend**: When `PUT /api/layout` is called, broadcast to all connected WebSocket clients
3. **Frontend**: Handle `LAYOUT_CHANGED` message, call `dockviewRef.current.fromJSON(payload)`

This gives you instant cross-browser layout sync without polling overhead.
